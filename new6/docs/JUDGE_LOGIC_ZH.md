# 六题 Judge：测量什么，如何算分

目标是交出下游能够核对、使用并在题面指定变化下继续使用的 Excel。每项从候选实际文件取证，区分来源正确、候选自身一致、实际响应。独立 Oracle 先给出参考事实，Evaluator 再读取候选；不使用文件名猜正负，不把合法不同布局判成错误。

## 统一算分

每项得分为已核实正确事实数除以预先固定的事实分母。三套 profile 复用同一项得分，各自加权求和。主方案为 capability_first；唯一通过条件是 SCORED 且未舍入分数 >= 0.70，没有额外门槛或封顶。balanced 与 ongoing_use 是同事实的敏感性对照，不代替主方案。具体数值容差属于各题 Oracle/判定函数；发布校验允许跨运行浮点表示的 1e-12 差异，该容差不用于改写 0.70 通过线。

动态任务在隔离副本更改题面允许的输入，清除缓存并用固定 LibreOffice 重算，分别测输出变化与不应变化的信息。静态 B 题接受常量；带公式的文件会实际重算。合法公式若当前引擎或解析器不能支持，则 JUDGE_ERROR、空分数并保留原因。正常完成、收集正常后的缺输出为 OUTPUT_MISSING，坏文件为 MALFORMED_OUTPUT；新交付政策将这两类记0分并计入失败和均分，仍保留原因与未取证的逐项事实。运行、供应商或收集故障继续单列待判。详见[交付评分政策](OUTCOME_SCORING_POLICY_ZH.md)。冻结运行保留旧回执，新汇总注明政策版本。

## 如何检查合理性

发布套件逐例声明期望状态、失分项和保持满分项，同时覆盖参考、真等价布局/公式、关键单错、混杂最终表示、重复/遗漏、缺输出、坏文件和合法解析限制。错误样本允许仍然过线：一个小错只扣其固定事实份额。运行失败会非零退出，不能因名字含 negative 就断言不通过。

每次评分固定代码、输入、权重和重算引擎；清单哈希不符时停止，结果记录原件哈希，容器断网且只读挂载原件。GitHub CI 重跑整套并再次评分八次实际尝试。新布局若无法可靠绑定，保留待判和证据；新增支持应单独校准并对同一原件重评，不能改权重制造低分。这个机制验证已覆盖的评分行为，无法预先证明任意未来文件都能被解析。

自然难度验收仍需固定系统与题目版本后的独立真实样本。本次八次尝试只能提供可解性和错误机制证据。外发负项与 agentic 解析要求的完整验收仍需单独对照，当前不声称已全部满足。
