# 题包里各类文件做什么

每道题现在只保留题面、输入、环境、参考、判据和实际评分依赖。先看[六题材料](../materials/README.md)，再按[统一入口](../repro/CURRENT_REPLAY.md)复评真实答卷。

| 目录或文件 | 审查时用途 | 参测Agent能否看到 |
|---|---|---|
| `instruction.md` | 题目场景与交付要求 | 能 |
| `task.toml` | 任务标签、资源、超时和环境配置 | 由运行器使用 |
| `data/input_files/` | 题目要求使用的完整材料 | 能 |
| `environment/Dockerfile` | 准备参测环境 | 构建后使用 |
| `solution/` | 参考工作簿与参考入口 | 不能 |
| `rubric.json` | 该题包冻结的评分条目 | 评分侧使用 |
| `tests/` | 真正执行判分的程序和独立答案依赖 | 不能 |
| `metadata/` | 来源、题目版本与输入身份 | 审查侧使用 |

`tests/`允许包含实际Evaluator的必要依赖。Oracle里的价格、记录和独立计算代码用于核对答案，不是无用数据，也不能当作Agent输入。每题的`tests/README.md`已列明具体用途。

此前导出时把开发任务目录整体带入了题包，所以还夹带了人工反例、试次回执、旧读取器快照和构建日志。本次已从六题目录移出这些文件，保留的评分代码、题面、输入及权重不变。

截图中的额外文件可这样区分：`fixtures/`是校准Judge的人工案例；`receipts/`是运行或评分记录；`JUDGE_CONTRACT.md`是判分约定，不是新增的做题要求。校准案例放到独立的[验证目录](../validation/README.md)，历史材料转入本地归档。`metadata/`只保留来源与版本说明，不用它堆放试跑历史。

首页只展示当前采用的成绩。其他配重试验与旧版本不作为最终成绩入口；复现当前成绩所必需的原答卷、实际回执和Judge快照仍在`results/`和`repro/`中保留。重复评分回执不是新的Agent样本。
