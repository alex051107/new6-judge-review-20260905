# 六道专业Excel任务：测量目标、现有结果与审查问题

这次按原来的A、B、C三轨能力目标，重新设计了六道Excel任务，主要看Agent能否读懂专业材料，交出别人拿到后能核对、能继续用的工作簿。题面、输入、参考、真实答卷和离线评分脚本都已整理到GitHub，任务可以实际运行，结果也有逐项依据可查。

新题更强调计算前后是否接得上、分析对象有没有遗漏、文档规则是否正确用到了结果中。已有成绩显示，部分任务比前15题更有挑战；也有题目仍被较好地完成。目前千问还在补跑，部分已收回答卷需要继续核对Judge的读取和重算结果，六题尚未全部完成难度验收。

这次主要请学长判断：这些能力是否值得测，评分规则是否测准了它们，以及应该通过哪些实际工作要求继续提高难度。布局和读取问题需要明确判断边界，避免技术识别范围决定业务得分。

## 六题测量什么，难在哪里

三轨共同检验工作簿能否交接给下一位使用者。下一位使用者应能找到结果对应的对象、期间、单位和依据；题面要求修改输入时，相关结果还应正确更新。A轨侧重专业计算关系，B轨侧重分析范围与证据一致，C轨侧重文档规则落实。动态更新是其中一种检查方式，B类正确的静态分析也可以完成工作。

| 题目 | 场景与材料 | 交付及主要能力 |
|---|---|---|
| [A1 Amazon估值](../review/A1.md) | 用公开估值模型与方法说明复核经营预测 | 连接年度预测、再投资、现金流和估值；修改假设后，预测与估值按同一计算链更新 |
| [A2 长期增长](../review/A2.md) | 用LTGM模型和赞比亚初值比较投资路径 | 保持投资、资本和GDP逐年衔接；目标与过渡年改变后，整段预测正确响应 |
| [B1 零售月结](../review/B1.md) | 根据真实零售交易和月结政策解释两月变化 | 覆盖完整交易；销售、贷项、发票、贡献桥和SKU证据使用同一口径 |
| [B2 劳动力简报](../review/B2.md) | 根据三期统计发布更新旧分析 | 核对地区与期间，生成连续恶化名单，解释名单变化并保留来源 |
| [C1 工程成本](../review/C1.md) | 根据成本PDF和重构修订往来更新底稿 | 区分有效报价、替换范围与未批准选项；把限定条件落实到可更新的成本计算 |
| [C2 邮政报价](../review/C2.md) | 根据资费文件为寄件请求报价 | 保留服务、重量上界、分区与单位规则；请求变化后选择、报价和总额正确更新 |

原始材料提供事实，项目重构具体工作请求。公开材料上的请求按重构场景描述，不写成真实客户委托。

这套题的价值在于检验专业知识能否落实到交付。实际工作中，得到一个数以后，还要解释它属于谁、依据什么、与其他结果是否一致，以及输入变化后是否仍然成立。六题把这些义务写进可检查的工作簿结果，给“会答题”和“能完成工作”之间的差别提供具体证据。人工审查要确认这些义务是否重要、是否由材料充分支持，再判断分值是否与业务影响相称。

### 现有结果测到了什么

现有分项已经能区分“当前数字正确”和“业务关系完整、后续工作仍能继续”。例如，Opus 5在C2的三份已评分答卷中，报价更新组平均得到15.15%的信用，其余业务项为89.29%；其中一份当前报价全部正确，修改请求后的更新项为0。这是值得对照原件复核的能力差别。C1两份答卷的更新项也为0，其余业务项平均为65.27%。

各系统的弱项并不相同。GPT-5.6 sol在A类模型关系和B1交易分析上较强，B2主要缺分在名单变化解释，C2的报价更新组均值为64.77%。Opus 5在B1的贡献分析组达到82.80%，销售、贷项与异常政策项却只有1.14%；过度强调贡献分析会淡化这一重要业务缺口。Qwen 3.8在A1的一份和B1的三份可评分答卷上表现很好，C2六份答卷的更新组均值为45.45%，其中两份更新满分，表现有明显分化。

这些百分比是各能力组内部的信用均值，用于定位失分，不是另一套正式成绩。全部分项与三个可直接下载的真实案例见[能力分析及原件核对](../results/current-effective-v2/MEASUREMENT.md)。A1一份Opus答卷和C2两份GPT答卷已知存在情景、表头或单位读取风险；相关缺分仍需人工核对。A2、C1的千问答卷尚无有效分项，当前不能评价这两组能力。

因此，六题已经把原定能力落实为可检查的交付，并观察到一些有解释力的差异；测量的有效性还需要独立人工判断支持。特别是要检查：业务确实完成的答卷是否被接受，业务关系被破坏时是否在对应项失分。A/B轨的部分高分同时说明，这些任务对相应系统还不够难。原15题与新6题测的是同类能力，但题目、覆盖率和Judge不同，现有表格支持逐题比较，尚不足以量化统一的难度提升幅度。

## Judge怎样评分，怎样区分异常

做题系统负责操作材料和提交工作簿，Judge负责核验文件，人工审查者负责检查场景、参考与判分是否合理。业务判分采用确定性程序，评分时未使用LLM Judge。数值、记录、计价规则和明确业务关系由程序与独立答案复算。

评分按以下顺序执行：

1. **先确认交付和运行状态。** 检查真实文件是否收集完整，并记录题面、输入、生成配置和Judge身份。正常结束却没有交文件、接口或容器中断、文件仍在收集分别记录。
2. **绑定业务含义与原文件位置。** 读取表头、业务ID、期间、单位和控件。支持的合理布局正常计分；含义无法可靠确定时留下读取原因，等待适配或原件复核。
3. **核对业务结果及适用更新。** 明确错值、漏记录、错对象或坏引用，在对应原有判据失分；需要更新的任务在原件隔离副本中修改真实输入，再用固定LibreOffice环境重算。
4. **保存逐项依据后汇总。** 每份答卷都留下结果记录，一份异常不停止整批。尚未核清的事实不补零，也不删掉后重新放大其余得分。未舍入分数达到70分是唯一通过规则。

正常执行和正确完成分开报告。已核实的6份Opus 5未交付记录均正常结束，日志中出现没有实际执行的文字工具调用；这些记录与API中断分列。已交文件如果只因Judge不认识布局而待判，也不会被直接列为业务失败。[运行与交付核对](../results/delivery-status-audit/README.md)保存了具体证据。

固定Judge另有参考、合法变体、业务错误和边界案例用于校准。同一A1真实答卷已经实际重复评分五次，逐项信用和总分标准差均为0；这项证据用于检查运行一致性。B1位图图表使用过按图片哈希保存的视觉读数，相关检查最多涉及总分约2.46%，转录来源身份还需补充。合理布局、公式重算和这类辅助证据是当前二次核验的重点。

### 哪些差异应接受，哪些需要限制判断

| 答卷情况 | Judge的判断范围 |
|---|---|
| 表名、位置、行序或单位写法改变，业务含义仍能唯一确定 | 作为合理等价实现接受。读取器尚不支持时先待判，不按版式不同扣业务分 |
| 缺少题面明确要求的业务对象、期间、单位或必需结果 | 确认缺失后，在相关既有判据失分，保留其他已完成部分的信用 |
| 数字出现了，但无法确定对应哪个请求或期间 | 核验对象关系是否真的缺失；无法排除读取问题时不先给业务失败结论 |
| 公式报错或没有缓存 | 用固定环境重算。确认坏引用或算错后按项失分；引擎不支持、重算未完成则保留技术待判 |

当前Judge的计算与分项计分方式有明确依据，读取层的覆盖范围仍是主要问题。正确识别后的数值和业务关系适合独立复算；识别不到时，程序还需要准确区分“内容缺失”和“合法表达未读出”。这张表列出应遵守的边界，当前程序尚未覆盖所有合法表达。对已有答卷继续遵守原题面，只有明示的交接义务才参与扣分。下一版可以规定最终结果必需的字段、ID、期间、单位和控件标识，让判断有明确依据，同时保留中间表和公式实现的自由。

## 表格布局不同怎么办，哪些论文可以参考

Excel可以跨表、横纵转换、使用多级表头或以图片展示。同一业务事实有多种合法表达。Judge需要先确认答案表达了什么，再检查它是否正确、完整；把位置识别和业务判定拆开，才能定位异常到底发生在哪一步。

**TabEval**把表格展开为事实，分别评价正确性与完整性。原方法用GPT-4或Claude展开事实，再用RoBERTa进行语义推断。我们借鉴它的事实与覆盖分离，将业务对象、字段、期间、单位和值作为核验对象；本版没有部署其模型评分器。[EMNLP 2024，§2与§5](https://aclanthology.org/2024.emnlp-main.1239/)

**GriTS**在二维表格中匹配子结构，给缺少部分行列的输出保留相应信用。它提示我们按实际覆盖评价完整性；允许行任意重排的交易任务，还要改用业务ID匹配，不能直接套二维顺序约束。[§3–4](https://arxiv.org/html/2203.12555v3)

**Semantic Table Evaluation**先定位解析输出中的表，再核对内容和表头关系，并检查匹配内容来自原输出。它使用LLM评估PDF表格。我们可借鉴原件追溯要求，让辅助定位只报告原文件中已有的位置，避免定位时补答案。[§3.2–4.2](https://arxiv.org/html/2603.18652v1)

**SpreadsheetBench与SheetCopilot**提供了更接近工作簿执行的参考：前者明确答案区域并使用多个输入检验解法，后者比较任务需要的属性、接受多个参考解，并区分执行完成与功能正确。这些做法支持我们明确最终交接字段，同时保留合理实现空间。[SpreadsheetBench §2.2、§2.4、附录C.5](https://arxiv.org/html/2406.14991v1) · [SheetCopilot §3.3](https://arxiv.org/html/2305.19308v2#S3.SS3)

**BlueFin**通过修改输入、重算工作簿和读取目标结果检查动态关系，实际采用LLM Judge。它为继续使用能力提供了验证思路；当前无在线LLM的方案仍需独立实现和校准这些检查。[§4与§4.2](https://arxiv.org/html/2605.30907v1#S4)

这些研究提供了可以复用的处理步骤：先定位必要内容，保留原件证据，再评价正确性与覆盖范围，最后检查适用的执行效果。它们没有给出一个可直接处理任意Excel业务布局的通用判分器。TabEval、Semantic Table Evaluation和BlueFin的模型环节也不能直接算作我们现有的确定性实现。

本版按离线、评分时不调用在线LLM的约束运行。外发附件本身还包含模型配置示例和agentic解析要求，这一差异已列入[要求核对](../review/REQUIREMENTS.md)，需要确认最终采用哪种验收方式。

短期先完成已收回答卷的离线核验，固定所用Judge与计算环境，对待判逐份确认位置、重算或交付原因。下一版可在题面中列出最终结果必需的字段、ID、期间、单位及控件标识，保留中间过程和公式布局自由；并补充改表名、转置、跨表、等价单位等合法案例。原件哈希绑定的位置映射可以作为后续读取辅助方案，需核验来源后再使用，新增要求不追溯处罚旧答卷。

## 偏容易的题，怎样增加真实要求

继续调整阈值或配重很难解决任务本身偏容易的问题。旧题中已有整组满分的任务，重新分配权重不会改变结果；NEW6的B1也有系统接近满分。加难应从交付增加了什么工作判断出发，并在生成新答卷前确定题面、答案和判据。

A轨可以增加需要协调的假设，例如同一投资变化如何同时影响资本、收入和现金流，或要求解释两条可行路径为什么给出不同结果。B轨可以增加有明确依据的跨期修订、例外交易或来源口径冲突，要求从完整明细解释差额。C轨可以增加同时生效的版本、范围、阈值和选项条件，要求确定哪些费用适用、哪些不能相加。每项新增条件都应来自材料或明确的重构请求，并有独立答案。

题面需要给足判断依据。为了接近真实工作，可以保留整理材料和选择实现方式的自由，但业务对象、期间、单位、计价政策和交付用途应当清楚。若任务允许向委托方追问，就明确把澄清信息作为交互的一部分；否则先补齐必要材料。QuestBench研究“缺信息时该问什么”，可帮助我们区分材料不足与推理失败，但它不是Excel题的现成验收方法。[QuestBench，§2–3](https://arxiv.org/html/2503.22674v1)

上述方向是下一版的设计建议，当前题面和已有答卷保持原要求。先请业务审查者判断新增工作是否真实、是否值得测，再用同版样本验证难度。

## 怎样组织评测环境，并扩大到150题

当前已经具备六题输入、参考与真实答卷，以及固定环境下重新读取工作簿评分的入口。要扩大题量，建议统一“运行、收集、读取、核验、统计”这些公共步骤，让每道题只补自己的业务规则与独立答案。评测运行框架（harness）的作用，是把各层结果和失败原因稳定保存下来，使业务错误、读取待判与运行失败能够分开追溯。

具体可以按这条流程组织：固定任务、输入和环境 → 收集最终原件 → 在隔离副本重算 → 绑定对象与结果位置 → 核对独立答案及适用更新 → 保存逐项事实并汇总。下一版可附一份简短交接清单，说明结果区域和可编辑输入，由程序核对清单是否对应原文件。OSWorld将结果提取函数与判定函数分开，并用不同解法检查误判，适合作为框架组织的参考；它同样保留了大量任务特定的核验函数。[OSWorld，§3.2](https://arxiv.org/html/2404.07972v2#S3.SS2)

批量获取题目可以从有授权的完整业务材料和正确工作簿出发，先建立可独立核验的完整交付，再按实际需求构造恢复、排错、分析或更新请求。SpreadsheetBench 2采用“整理完整参考工作簿—移除目标区域、注入可控错误或提出可视化要求—另外两位专家仅凭题面与输入独立作答”的流程。这比逐题临时编出输入和答案更容易复用，但仍需要业务专家确认。[SpreadsheetBench 2，§2.2](https://arxiv.org/html/2606.29955v1#S2.SS2)

建议先用这六题核清判分边界，再做一批跨来源试产，按30题、75题、150题逐步扩大；数量是本项目的推进建议。每道候选题依次检查来源与许可、材料充分性、独立答案、合法等价实现和业务错误案例，最后才进行模型难度验收。同一模板改数字要归入同一任务族，分别记录来源和变体，避免用大量近重复题代替业务覆盖。每批记录建题、人审和维护时间，以及读取待判、误拒正确答案和误收错误答案的比例，据此判断能否继续扩量。

潜在研究贡献可以放在“业务事实如何稳定核验”上：跨A/B/C任务统一记录对象、期间、单位和来源，在接受合理布局的同时，区分业务错误与尚不能判断，并让同一份事实证据支持复算、更新测试和人工审查。确定性计分、原子事实、多输入测试和输入扰动均已有研究先例。要证明这一组合有新价值，需要与固定位置、必要属性匹配及语义事实方法作对照，检验是否减少误拒而不增加误收，并报告人工成本与跨来源表现。目前这是候选研究方向，尚未完成对照实验。

## 这次希望得到哪些帮助

材料按每题“题面与输入、参考答案、真实交付、分项回执、审查意见”组织，方便从业务问题一路核对到文件和单元格。[六题审查入口](../review/README.md)提供可填写表格；[复跑入口](../repro/README.md)分别说明如何重读已有Excel评分、如何仅复算公开分项，以及如何给自有文件评分。[六题输入、参考和真实答卷](../materials/README.md)均已放到公开仓库，可直接查看和下载。

请学长重点帮忙判断以下几件事：

1. **能力目标与配重是否合理。** 这些要求是否对应有价值的实际工作，现有判据是否覆盖了主要能力，分值是否与业务影响相称？参考答案和正反例是核对依据。
2. **Judge的判断边界是否公平。** 哪些字段和关系必须交清楚，哪些布局差异应接受；遇到无法读取的表格，应补什么证据才能判断，而不是直接把技术异常算成能力失败？
3. **难度应该加在哪里。** A轨可增加需要协调的年度假设和情景关系；B轨可增加有明确依据的跨期、跨来源核对及例外交易；C轨可增加需要合并判断的版本、范围、阈值和计价条件。这些方向都应先建立正确答案和业务依据，再形成新版本题目。

4. **哪部分可以先验收，怎样支持扩量。** 先审查材料、参考、判分和复跑已齐备的部分；难度未达要求的任务继续作为候选。上述任务族构造和分层评测方式是否适合扩到150题，哪些步骤需要业务专家参与？

后续加难以这些业务要求为单位。每增加一项，都要能说明使用者为什么需要它、Agent能从哪里获得必要信息，以及正确与错误交付怎样区分。数据规模、文件数量和格式要求只有在增加真实判断负担时才有意义。新增任务版本单独运行和验收，当前答卷继续使用原来的要求。
