# NEW6-C-PARCEL-TARIFF-001｜真实邮政价目表到动态寄件报价工作簿

主能力：准确还原多层表头、重量上界与计价范围，再按客户输入使用价格

本文件仅给构造者，不得挂载给任务Agent。

## 取材
USPS官方PriceChange页面Final July2026 Notice123，固定effective2026-07-12，不用October proposed。已经视觉读取印刷5/7页的表头、单位与footnotes。下载本地后提供完整63页PDF或封面+5/7页完整页（保留全部脚注和原页标，附摘录manifest），只改变任务文档范围不改PDF数据。首轮建议保留这3页使文档操作可控，不偷偷隐藏适用的脚注。

## 输入/真值隔离
给原PDF和quote_requests.csv（本包已生成12条，明确合成请求）。官方同版Excel/CSV只给私有Oracle核对，不给Agent，否则C轨退化成读取机器结构数据。Oracle要先对照同版本PDF。任务不会宣称合成请求是实际邮寄工作。

## 计价逻辑
每行键为service+weight_unit+upper_bound+zone+effective_date，不能把oz行当lb，不能按显示行号套另一服务。Ground ounce upper limits与1lb价格目前可有相同数值，但仍保留原边界身份。Priority按其实际上界；报价权重使用Decimal，浮点边界不模糊。只在范围内调用；规则不足不能外推。

## 输出要求
完整价目表本体是主要C能力，不仅把12个报价数字算出来；相反价目表正确也不能代替缺失报价和batch输出。每项报价显示两个产品价格、选中产品和价格。来源可一组rate-row共享页定位，不强迫每个单元格重复长URL，但服务和重量行要能回到原表。

## 独立验证
下载官方机器表并核对本题192个单价；再用独立线性band扫描计算12请求。结构金标与计算规则分开；没有机器数据时双人/两个独立提取途径逐区间核对，不能让同一个抽取器自证。测试4→4.1oz、8→8.1oz、1→1.01lb及zone1→8，至少一次联合变化。只引用已声明输入，不加DIM复杂度。

## 注意
这是一份真实价目表上的重构工作底稿。是否困难需要模型试跑；192格不自动意味着高难度。纸质来源字段和适用范围占大头，不能为追求method novelty降成次要。
